C0VM ARCHITECTURE & MACHINE SEMANTICS

Stack-Based vs. Register-Based Architecture

Virtual execution environments divide into two fundamental paradigms: stack architectures (C0VM, JVM, WebAssembly, CPython) and register architectures (x86, ARM, LuaJIT).

METRIC STACK VM (C0VM, JVM, WASM) REGISTER VM (X86, ARM, LUAJIT)
Operand Location Implicit (top of operand stack S) Explicit registers (r0, r1, r2)
Instruction Density 1 Byte opcodes (compact binary size) 2 to 4 Bytes (must encode register indices)
Compiler Complexity Minimal (direct post-order AST walk) High (NP-hard Graph Coloring allocation)
Hardware Neutrality Complete (no assumption on register count) Fixed virtual register count assumed

Evaluating an arithmetic expression such as (a + b) * c:

vload a      # Push variable a to top of S
vload b      # Push variable b to top of S
iadd         # Pop a, b -> Push sum (a + b)
vload c      # Push variable c to top of S
imul         # Pop (a + b), c -> Push product ((a + b) * c)

Zero CPU register allocation is required by the front-end compiler, maximizing binary portability across machine targets.

The Three Memory Subsystems

+------------------------------------------------------------------+
|                           C0VM Memory                            |
+--------------------------------+---------------------------------+
|          Call Stack            |              Heap               |
|  +--------------------------+  |  +---------------------------+  |
|  | Frame 2: factorial(n=1)  |  |  | Dynamic Arrays (NEWARRAY) |  |
|  |   V[0]=1, pc=0x000c      |  |  |   count, elt_size, *data  |  |
|  |   S: [1]                 |  |  +---------------------------+  |
|  +--------------------------+  |  +---------------------------+  |
|  | Frame 1: factorial(n=2)  |  |  | Struct Blocks (NEW)       |  |
|  |   V[0]=2, pc=0x000c      |  |  |   raw byte fields         |  |
|  |   S: [2]                 |  |  +---------------------------+  |
|  +--------------------------+  |  +---------------------------+  |
|  | Frame 0: _c0_main()      |  |  | Immutable String Pool     |  |
|  |   V[0]=0, pc=0x0002      |  |  |   null-terminated chars   |  |
|  |   S: []                  |  |  +---------------------------+  |
|  +--------------------------+  |  +---------------------------+  |
+--------------------------------+---------------------------------+

1. Call Stack (Activation Records): Each function invocation allocates an isolated execution frame holding code pointer P, program counter pc, and local variables V[0..num_vars-1]. Recursion allocates new frames sequentially; returns deallocate the active frame and restore the caller.

2. Operand Stack (S): LIFO evaluation scratchpad. Arithmetic, logic, and comparison instructions operate strictly on the top elements of S.

3. Dynamic Heap: Allocated via host malloc for structs (NEW) and runtime-bounded arrays (NEWARRAY). Memory outlives the frame that allocated it.

Formal Stack Transition Rules

Instructions in C0VM are mathematically formalized as deterministic state transitions over the operand stack S:

OPCODE STACK TRANSITION BEHAVIOR
bipush b S -> S, b Push 8-bit immediate sign-extended to 32 bits
vload i S -> S, V[i] Copy value from local variable slot i to top of stack
vstore i S, v -> S Pop top of stack and assign to local variable slot V[i]
iadd S, x, y -> S, (x + y) Two's-complement signed 32-bit addition
newarray s S, n -> S, a Allocate bounded array with length n; push pointer address a
aadds S, a, i -> S, &a[i] Verify 0 ≤ i < a.count; push element memory address
imstore S, p, v -> S Store 4-byte integer v into memory cell at address p

Dispatch Architecture & Branch Prediction

The instruction dispatch loop represents the primary performance bottleneck in bytecode interpreters:

1. Switch-Based Dispatch (Implemented in C0VM):

while (true) {
    uint8_t op = *pc++;
    switch (op) {
        case IADD: ... break;
        case ISUB: ... break;
    }
}

Portable across ANSI C compilers. However, every instruction branches through a single shared indirect jump, degrading CPU branch history buffers.

2. Direct Threaded Code (Computed Goto):

static void* dispatch_table[] = { &&do_iadd, &&do_isub, ... };
#define DISPATCH() goto *dispatch_table[*pc++]

do_iadd:
    // ... add ...
    DISPATCH(); // Branches directly to next instruction handler

Each opcode handler ends with an independent indirect jump directly to the subsequent opcode handler. This matches hardware branch target buffer (BTB) patterns, eliminating central switch overhead and accelerating execution by 15% to 30%.
